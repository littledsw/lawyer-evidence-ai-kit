# evidence-kit · 证据目录 → 证据册 PDF

把「一份证据目录 + 一包格式各异的证据材料」排成**一份可直接提交的 PDF**：
前面是证据目录表（序号 / 证据材料名称 / 证明目的 / 页数），后面是全部证据原件，
**从第 1 页连编到底**，目录里的 `页数` 就是实测页区间（`1-5`、`6-9`、`10-12`）。

本仓库是独立项目，不绑定劳动仲裁：诉讼、行政复议、任何需要「证据目录 + 连编页码证据册」
的场景都用同一套。默认不联网、不调用任何 LLM——全部脚本化，可离线跑。

## 不变量（改代码前先读）

1. **原件字节不动**：JPEG 以 `DCTDecode` 直通（把 PDF 里的流解出来，与源文件逐字节相同），
   PNG 走 `FlateDecode`（逐像素无损）。不重压缩、不锐化、不裁切、不旋转。
2. **页数只从分页计划出**：目录里的区间必须等于渲染后实测页区间，`layout.verify()` 对不上就整册作废。
   页数不是猜的，是排出来的。
3. **页码只在页脚 18mm 留白区**，版心高度已扣掉它，永不压字。
4. **版面恒为 A4 竖版**；紧凑模式（一页多张）也不横过来。
5. **材料解析不了就报错**，列进报告，绝不静默丢弃。

## 安装

```bash
uv venv .venv && uv pip install --python .venv/bin/python -e ".[dev]"
```

依赖只有 4 个：reportlab（画 PDF）、pypdf（合并/变换 PDF 页）、pillow（读图片尺寸）、PyYAML。
macOS 上字体用系统自带的 `Songti.ttc`（标题/Songti SC Bold、正文/STSong）。

## 用法

```bash
# ① 最快：材料文件夹自己就是目录（每个子文件夹 = 一个证据组）
.venv/bin/python -m evidence_kit dump --materials 案件/materials --out 案件/catalog.yaml
#    → 生成目录草稿，填名称与证明目的

# ② 出册
.venv/bin/python -m evidence_kit build \
  --catalog 案件/catalog.yaml --materials 案件/materials --out 案件/out
```

产物：

| 文件 | 内容 |
| --- | --- |
| `证据册.pdf` | 目录页 + 证据页，交给人看/打印/提交的那一份 |
| `证据目录.pdf` | 只有目录页（改字、单独递交用） |
| `证据页.pdf` | 只有证据页（1..N 连编） |
| `report.json` / `README-核对报告.md` | 页码对照表、每份材料落第几页、DPI、提示与阻断项、待人工确认项 |

常用开关：`--compact`（一页 2 张，页数减半）、`--per-page N`（一页 N 张）、
`--auto`（忽略目录文件，按子目录分组）、`--allow-low-dpi`（放行 <100 DPI 的糊图）。

## 目录格式（catalog.yaml）

```yaml
case:
  title: 证据目录
  submitter: 崔某某        # 留空则打印空行，不编造
  agent: 王某某
  date: ""                # 留空 → 打印「年　月　日」
groups:                   # 一个 group = 屏幕表格里共享「证明目的 / 页数」的一格
  - proves: |
      1:证明申请人月工资标准为 4500 元；
      2:证明工资由劳务公司实际发放；
    rows:
      - no: 1
        name: 银行工资流水
        files: 01_银行工资流水        # 目录 / glob / 单文件都可以
  - proves: 证明其在某公司担任司机并接受其管理。
    rows:                          # 一个证明目的覆盖两个序号（合并单元格）：
      - no: 3                      # 两组材料共用一格证明目的、一格页数，页数连排
        name: 中国石化加油IC卡台账对账单
        files: 04_加油台账
      - no: 4
        name: 停车缴费截图
        files: 05_停车缴费
```

`proves` 不填 → 目录里显示「（证明目的待补）」，并进报告的「需人工确认」清单。
**机器不替你编证明目的**（那是实体判断）；后续会接「规则模板优先、LLM 兜底」的补写，
但补出来的一律标 `proves_source: auto` 并进待复核清单。

## 版面规则（实测数字）

版心 186×267mm（A4 210×297，上下 12/18mm，左右 12mm）：

| 材料 | 单页一张 | 紧凑模式两张并排 |
| --- | --- | --- |
| 竖屏手机截图 1170×2532 | 印 123×267mm，有效 **241 DPI** | 印 90.5mm 宽，字号缩到 77% |
| A4 扫描件 PDF | 矢量，满版心 | 矢量，半宽 |
| 超长滚动截图 1170×9200 | 按宽切片 **6 页**，切缝重叠 8mm | 切片永远独占一页（不并排） |

- DPI **<100 直接拒绝出册**（会糊），<150 提示；
- 长截图判定阈值：高/宽 > **2.6** 才切（手机整屏截图约 2.16，不切）；
- 切缝重叠 8mm，避免把一行字切成两半。

## 现状（2026-10）

**已实现**：目录 yaml/json + 材料目录/glob 解析；图片（PNG/JPEG/HEIC/TIFF，HEIC 经系统 `sips`
一次性转 JPEG q100 并在报告点名）；PDF 逐页重排（向量缩放，无损）；长截图切片；一图一页 /
`--compact` 两图一页 / `--per-page N`；组内多材料共用证明目的与页数；页码连编 + 页脚组标；
页码对照报告；17 项测试（含 JPEG 字节直通、页数自证、低分辨率拒绝、切片重叠）。

**未实现（按优先级）**：

1. **目录的自动解析**：docx / xlsx / PDF 表格、截图 OCR（macOS Vision，本地）。当前只吃 yaml。
   设计走两段式：`parse` 出草稿 yaml → 人工改字 → `build` 排版，机器不替人定证明目的。
2. **组内按时间排序**：微信聊天截图按截图内时间戳升序（OCR + 排序核对表），当前是按文件名自然序。
3. **证据目录 docx 输出**（可编辑版，仲裁委/法院常要改字）。
4. **证据详单附表**（每条证据的子项明细 + 所在页），内部核对版。
5. **200MB / 80 文件的上传闸门** + 本机 HTTP 服务（仅 127.0.0.1），再往后才是 macOS app。

## 红线

- 客户材料不出本机：本仓库不联网、不上传；OCR 用系统 Vision，录音转写用本地 whisper。
- 当事人信息、案件材料、产物不进 git（见 `.gitignore`）。
- 产物是律师工作底稿，正式提交前须人工复核；生成物带「需人工复核」项的报告一并交。
